# SVN Manager（SVN 管理器）

单文件 Windows 桌面程序（Rust + egui，无运行时依赖），用来管理多个 SVN 工作副本：
自动寻找 `svn.exe`、更新 / 上传（提交）/ 查看提交记录 / 左右分栏逐行对比 / Beyond Compare 联动 /
内置版本自动更新（自带零依赖服务端脚本）。

> 全中文界面，浅色 / 深色主题跟随系统，也可一键切换。exe 约 10 MB，双击即用。

## 功能特性

### 目录管理

- **自动寻找 svn.exe**：按 `SVN_MANAGER_SVN` 环境变量 → `PATH` → 注册表（TortoiseSVN）→
  各磁盘常见安装目录 → 磁盘浅扫描的顺序探测，并用 `svn --version` 验证；也可在设置里手工指定。
  顶部状态灯实时显示「已连接 / 未连接 / 检测中」，每个目录行左侧还有独立状态灯（悬停看原因）。
- **添加目录**：「选择文件夹」、手工输入、或直接把文件夹拖进窗口；配置持久化。
- **目录行操作**：`⬇ 更新`、`⬆ 上传`、`🕘 历史`、`📂 打开目录`、`更多`（修改别名 / 修改仓库地址 /
  清理 / 解决冲突 / 排序 / 复制仓库 URL）、`移除`（只移出列表，不动磁盘文件，两次点击确认）。
  整行可点击选中，双击直接打开目录文件夹。
- **修改仓库地址（relocate）**：换服务器 / 端口 / 协议时，只需填新地址，窗口先预览改写后的完整
  地址再执行；只改 URL 元数据，不动本地文件，写错也只是执行失败，不会弄坏工作副本。
- **开机自动启动**：设置 → 常规里勾选即可（写当前用户注册表 Run 键，不需要管理员权限）。

### 提交记录与对比

- **一律读服务器记录**：`svn log -v -r HEAD:1 -l N --xml`，页头显示「服务器 rX / 本地 rY」，
  本地落后时提示「本地待更新」。默认只看本机 svn 登录人的提交（可在设置中更改），随时可切。
- **条数可调、可临时不限**：页头「条数」控制扫描条数；勾选「不限」可临时拉取全量记录
  （不写入设置，取消后恢复）。
- **左侧版本列表 / 右侧涉及文件**：文件按 新增绿 / 修改蓝 / 删除红（替换紫）着色，
  过滤关键字在版本号、作者、说明、路径所有命中处高亮。
- **左右分栏逐行对比**：双击某个版本（或涉及文件的某条记录），弹出「上一版本 ↔ 本次版本」
  的并排对比：删除行红色只在左列、新增行绿色只在右列、两侧都有即本次改动的行；
  行号与代码同行对齐，`@@` 表头标蓝作为行号起点，可框选复制，超长行自动折行。
- **单文件提交记录**：鼠标悬停「涉及文件」某行，行最右出现「查看提交记录」按钮，查看该文件
  自己的版本历史，再双击某条即跳到那一次的左右对比。
- **忽略空白与换行开关**：`.xml` 默认勾上（编辑器整体改缩进 / 换行符时不会被整份标红），
  其余文件默认看原始差异；忽略后没有实际改动时会明确说明「只是缩进 / 空格 / 换行符变了」。

### 提交流程

- `svn status --xml` 列出待提交内容，自动识别 新增(A) / 修改(M) / 删除(D) / 替换(R) /
  未版本化(?) / 已丢失(!) / 冲突(C)，按类型着色，每行复选框可勾选。
- **新增 / 删除可与修改一并提交**：勾选的未版本化项自动 `svn add`、已丢失项自动 `svn delete`，
  然后一次 `svn commit`；提交前重读状态，没进调度的条目会列为「已跳过」。
- 提交备注不必填、不预填；通过临时 UTF-8 文件传说明，中文不乱码。
- 点选文件即读 `svn diff`（增删行着色），可重新读取或交给 Beyond Compare 对比。

### Beyond Compare 联动

- 顶部按钮按当前选中目录匹配 BC 里已保存的文件夹对比记录（`BCSessions.xml`），命中直接打开；
- 提交页里用 `svn cat -r BASE` 导出基准版本，让 BC 并排对比「BASE ↔ 本地」；
- BC 路径自动寻找（环境变量 → PATH → 注册表 → 常见安装目录），也可在设置手工指定。

### 界面与其他

- **主题**：默认跟随系统，顶部按钮在 跟随系统 → 浅色 → 深色 间循环，标题栏即时生效；
- **输出记录**：底部面板实时显示每条命令与输出（UTF-8/GBK 自动识别），可清空、自动滚动；
- **设置持久化**：svn 路径、BC 路径、仓库账号、提交记录条数、自动刷新间隔、主题、
  更新服务端地址等全部写入配置文件；
- **中文字体**：优先 PingFang SC，自动回退微软雅黑 / 等线 / 黑体等，任何机器不会因缺字体崩溃；
- 启动即最大化，exe 内嵌应用图标（含窗口 / 任务栏图标）。

## 快速开始

1. 下载或构建 `svn_manager.exe`（见 [构建指南](#构建指南)）；
2. 双击运行，程序自动寻找本机 `svn.exe`；
3. 把工作副本文件夹拖进窗口（或点「添加」选择文件夹）；
4. 每行按需点 `⬇ 更新` / `⬆ 上传` / `🕘 历史`。

## 构建指南

### 一键构建

```bat
build.cmd
```

脚本会自动寻找 MinGW-w64 工具链（优先 `tools\mingw64`，其次 msys2 常见位置，最后 PATH），
并在缺少 `libpthread.a` 时自动从 rustup 补齐；每一步出错都会停住显示原因。

产物：`target\release\svn_manager.exe`（单文件，无运行时依赖）。

### 手动构建

```bat
:: 仅需一次：安装 Rust（GNU 工具链，无需 Visual Studio）
winget install Rustlang.Rustup
rustup default stable-x86_64-pc-windows-gnu

cargo build --release
```

> 需要 MinGW-w64（`gcc.exe` + `dlltool.exe` + `windres.exe`）。也可改用 MSVC 工具链：
> `rustup default stable-x86_64-pc-windows-msvc`（需装 Visual Studio 生成工具，图标走 `rc.exe`）。

### exe 图标

图标链路：`rabbit.png` → `icon\make_ico.ps1` → `icon\svn_manager.ico`（16–256 共 7 个尺寸），
`build.rs` 用 windres 编进 exe（文件 / 窗口 / 任务栏图标）。想换图标：替换根目录 `rabbit.png` 后：

```bat
powershell -NoProfile -ExecutionPolicy Bypass -File icon\make_ico.ps1
build.cmd
```

## 版本自动更新（客户端 + 服务端）

程序内置一套轻量的自动更新机制，**服务端只需静态文件托管**。

### 客户端机制

1. 启动 3 秒后后台读取「设置 → 版本更新 → 服务端地址」下的 `latest.json`
   （地址为空则安静跳过；内网地址自动绕过系统代理）；
2. **有没有新版按文件判**：把源上的 `sha256` 与本地正在运行的 exe 的 sha256 一比，
   不同就提示——同一个版本号重新发布的构建也能被发现（源没给 `sha256` 或本地
   exe 算不出哈希时，退回版本号比较）；
3. 顶部栏常驻「↑ 新版本 Vx.y.z」按钮，点击弹出确认对话框（版本号、发布时间、
   更新说明多行展示；版本号没变时不做新旧对比，只标注「内容有更新」）；
4. 确认后**在程序内下载**新 exe → 用 sha256 校验 → 生成收尾脚本并退出：
   脚本等旧进程退出后覆盖原程序（被占用自动重试）→ 重新启动 → 脚本自删。

### 服务端协议（latest.json）

```json
{
  "version": "1.2.0",
  "url": "files/svn_manager_1.2.0.exe",
  "notes": "修复了 xxx\n新增了 yyy",
  "sha256": "发布时自动写入；客户端拿它判有没有新版，下载后也用它校验",
  "published_at": "2026-09-07 10:00:00"
}
```

- `url` 相对 `latest.json` 所在目录拼接，写完整 http(s) 地址也可以；
- `notes` 支持换行（`\n`），客户端按原文多行展示；
- 版本号只用于界面显示，写法不限（`1.2.4` / `1.2.4-加固` / `V1.2.4` 都行；
  客户端只剥掉开头的 `v` / `V`）：客户端判更新看的是 `sha256`，与内嵌版本
  （`Cargo.toml` 的 `version`）对不上也不会反复提示。

### 发布流程

**方式一：拖拽发布（推荐）**

把新版 exe 拖到 `tools\publish_drop.bat` 上：

1. 提示填写版本号：回车 = 沿用默认（文件名版本 > version.txt > 上一发布版本）；
   也可直接写，**格式不限**（`1.1.2` / `1.2.4-加固` / `V1.2.4` / `2026.09.17` 都收）；
   `+` = 默认值补丁号+1，`++` = 次版本号+1（默认值不是数字和点时提示手填），`q` = 取消；
2. 提示填写更新说明：输入中的字面 `\n` 会转成真实换行；整段多行建议放 `notes.txt`
   （exe 旁或脚本旁，自动沿用）；
3. 脚本把 exe 拷入 `files/`、计算 SHA256、生成/覆盖 `latest.json`。

**方式二：命令行发布**

```bat
python tools\update_server.py D:\update_root --publish svn_manager_1.2.0.exe --notes "修复xxx"
```

### 托管更新服务

零依赖脚本自带静态服务（Python 3.8+，无需任何第三方库）：

```bat
python tools\update_server.py D:\update_root --serve --port 8666
```

客户端「设置 → 版本更新 → 服务端地址」填 `http://<本机IP>:8666`。
用 nginx / IIS 托管同一目录效果相同。版本目录的确定顺序：
命令行参数 > 脚本旁 `update_root.txt` 第一行 > 脚本旁 `update_root\`。
发布只写文件，服务运行中无需重启，客户端下次检查即生效。

## 配置与运行期文件

| 文件 | 用途 |
|------|------|
| `%APPDATA%\SVNManager\config.json` | 配置（目录列表、svn/BC 路径、账号、条数、刷新间隔、主题、更新服务端地址、开机自启等）；可用记事本编辑，带 UTF-8 BOM 也能识别 |
| `%APPDATA%\SVNManager\panic.log` | 异常日志（界面程序没有控制台，panic 写在这里；有新增内容时界面顶部会提示） |

- 仓库账号明文保存，慎用共享机器；
- 所有 svn 命令都带 `--non-interactive`，需要交互输入（首次接受证书等）时直接返回错误并显示在输出面板；
- 主题默认跟随系统，可随时用顶部按钮或设置切换。

## 开发与测试

```bat
cargo test
```

测试不依赖真实 SVN 仓库，覆盖面包括：

- 目录行「整行可点、行内按钮互不抢占」（无头 egui 上下文复现）；
- 搜索高亮分段（中文按字符边界切分不 panic）；
- 任务池「只读任务不算写操作、后台线程崩溃会回报」；
- 差异参数（`--internal-diff` 与 `-x "-w --ignore-eol-style"` 的参数组合）；
- 提交目标名单（? / ! 与 A/M/D/R 的取舍、待 add / 待 delete 名单）；
- 字体绑定（未绑定的字族会让 epaint 排版 panic，这里钉住）；
- 左右分栏排版（按实际画出的文字断言行号对齐、无重叠、折行而非裁切）；
- 历史页悬停按钮（位置正确、悬停不消失、行不抖动）；
- Beyond Compare 会话解析（嵌套文件夹记录、无名空节点、目录匹配）；
- exe 图标完整性（ICO 目录逐项校验，坏图标构建不报错但会悄悄退回默认图标）。

## 说明与限制

- 依赖命令行 `svn.exe`；TortoiseSVN 安装时需勾选 *command line client tools*；
- 凭据默认用 svn 自己的缓存，需要账号时在「设置 → 仓库账号」填写；
- `tools\mingw64`（构建用工具链）不随仓库分发，可自行准备 MinGW-w64 或改用 MSVC 工具链；
- 自动更新下载与校验在程序内完成，收尾脚本只负责覆盖重启——避免带下载特征的脚本被安全软件查删。
