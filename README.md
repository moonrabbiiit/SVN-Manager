# repo-manager（仓库管理器）

单文件 Windows 桌面程序（Rust + egui，无运行时依赖），用于在同一界面下统一管理多个 SVN / Git 工作副本，覆盖检测、更新、提交、历史查看、逐行对比、版本回退、本地差异比对、AI 工作日志与版本自动更新等环节。

> 全中文界面；浅色 / 深色主题跟随系统，亦可手动切换。可执行文件约 10 MB，双击即可运行。

## 功能特性

### 仓库后端

程序同时支持 SVN 与 Git 两类仓库，依据目录中的 `.svn` / `.git` 自动判定后端类型，二者共用同一套界面与数据结构：

| 操作 | SVN | Git |
|------|-----|-----|
| 状态检测 / 更新检查 | `svn status`、`svn log` | `git fetch` 后统计落后上游的提交数 |
| 更新 | `svn update` | `git pull --ff-only`（不产生合并提交） |
| 提交 | 自动 add / delete 后 `svn commit` | `git add -A` + `git commit`，随后自动 `push` |
| 版本回退 | `svn merge -r HEAD:<版本>` | `git revert --no-commit` / `git restore --source` |
| 提交记录 | `svn log -v --xml` | `git log --name-status` |
| 修改仓库地址 | 支持（relocate） | 不适用（菜单中不显示） |
| 清理 / 解决冲突 | 支持（冲突逐条选收场策略） | 不适用 |
| 分支显示 | — | 目录行显示当前分支 |

- 「可更新 N 项」：SVN 按待更新条目数计，Git 按落后远端的提交数计；
- 回退产物均为本地未提交改动，经核对后由用户自行上传，不会直接改动远端；
- Git 回退要求目录为仓库根；提交备注必填（SVN 可留空）。

### 目录管理

- **自动寻找命令行工具**：`svn.exe` 依次按 环境变量 → `PATH` → 注册表（TortoiseSVN）→ 常见安装目录 → 磁盘浅扫描 的顺序探测，并以 `svn --version` 验证；`git.exe` 与 Beyond Compare 亦有各自的探测链路，均可在设置中手工指定。顶部状态灯实时显示「已连接 / 未连接 / 检测中」，各目录行另有独立状态灯（悬停可查看原因）。
- **添加目录**：支持「选择文件夹」、手工输入路径，或直接将文件夹拖入窗口；配置持久化保存。
- **两种主页样式**：右上角可切换「详细 / 简约」。详细样式为整行卡片，集中呈现版本、标记、待提交 / 冲突 / 本地差异计数与全部操作按钮；简约样式为正方形卡片，以计数徽标（可更新 / 待提交 / 本地差异）与圆形「+」菜单收纳全部操作。
- **分组与标记**：目录可设置分组（可折叠）与文字标记（自定义颜色），支持按住一秒后拖拽排序、跨分组移动，相关下标引用自动重映射。
- **目录行操作**：更新、上传、历史、打开目录、「更多」菜单（修改别名 / 分组 / 标记、修改仓库地址、绑定对比对象、差异过滤与提交屏蔽、导出本地差异报告、清理、解决冲突、排序、复制仓库 URL）、移除（仅移出列表，不改动磁盘文件，需两次确认）。整行可点击选中，双击直接打开目录文件夹。
- **修改仓库地址（relocate）**：更换服务器 / 端口 / 协议时填写新地址，执行前先预览改写结果；仅修改 URL 元数据，不影响本地文件。
- **批量操作**：工具条提供全部检测、全部更新、全部上传（各目录共用一条提交说明、逐目录勾选参与）、批量修改仓库地址、批量设置分组 / 标记。
- **自动刷新**：默认每 120 秒自动检测一轮（间隔可调，设为 0 关闭），仅在空闲时执行；提交 / 更新 / 维护操作完成后自动补刷一次。
- **开机自启动**：设置 → 常规中勾选即可（写入当前用户注册表 Run 键，无需管理员权限）。

### 提交记录与对比

- **一律读取服务器记录**：`svn log -v -r HEAD:1 --xml` / `git log --name-status`，页头显示「服务器版本 / 本地版本」，本地落后时提示「本地待更新」。默认仅显示本机账号的提交，可随时切换。
- **条数可调**：页头「条数」控制读取范围（1–2000），勾选「不限」可临时拉取全量记录（不写入配置）。
- **日期区间过滤**：提供 当天 / 一周 / 一个月 / 一年 / 所有 / 自定义 六档；自定义支持手输日期并附带月历选择器。区间模式下条数限制失效。
- **搜索**：对版本号、作者、说明、文件路径全量过滤，支持 区分大小写 / 正则 / 整词 三种模式，并提供逐处命中导航与高亮。
- **左侧版本列表 / 右侧涉及文件**：文件按 新增绿 / 修改蓝 / 删除红（替换紫）着色。
- **左右分栏逐行对比**：双击某次提交（或其涉及文件的记录），弹出「上一版本 ↔ 本次版本」的并排对比：删除行红色仅现于左列、新增行绿色仅现于右列、两侧皆有者为本次改动行；行号与代码对齐，`@@` 表头标蓝作为行号起点，支持框选复制与超长行自动折行，可最大化 / 还原（Esc 关闭）。
- **单文件提交记录**：悬停「涉及文件」某行，通过行末「操作」菜单查看该文件独立的版本历史，双击某条记录同样跳转至左右对比。
- **忽略空白与换行开关**：`.xml` 文件默认勾选（编辑器整体调整缩进或换行符时不致整份标红），其余文件默认显示原始差异；忽略后若无实质改动，将明确提示「仅缩进 / 空格 / 换行符变化」。

### 版本回退

- 提交记录页选中某次提交后，可将代码回退至该版本：详情面板提供「回退整个目录到此版本」，涉及文件行末「操作」菜单提供「回退此文件」，均需两步确认；
- 实现为 `svn merge -r HEAD:<所选版本>` / `git revert --no-commit <所选版本>..HEAD`（单文件走 `svn merge` / `git restore --source`），改动仅落在本地工作副本，与普通改动一样计入「待提交」，由用户核对后自行上传，或以「撤销修改」还原；
- `svn merge` 的位置参数是「合并源 + 合并目标」，本程序把同一条路径写两遍：只写一遍时 svn 会把它当合并源、目标退化成程序当前目录；
- 注意该操作并非「仅撤销所选那次提交」：所选版本之后至当前的全部改动将一并倒回；
- 目录存在未提交改动时将提示其与回退结果合并；存在未解决冲突时不再整体拦截——SVN 只拒绝「回退正好落在冲突节点上」的那部分，且拒绝时一个文件都不改：回退单个文件只看它自己，回退整个目录时只要目录里有一个冲突文件，整趟就会被拒绝（确认窗口按这两种情形分别写明）。

### 冲突处理

- 「更多 → 解决冲突」（SVN 目录）列出该目录里必须先人工处理的条目，逐条给一行：勾选框 + 文件名 + 收场策略；
- 每条可选四种收场：`保留手头这份`（`resolve --accept working`，冲突标记原样留在文件里）、`用我的版本`（`mine-full`，服务器那次改动从这份文件里消失）、`用服务器版本`（`theirs-full`，我的改动消失）、`丢弃本地改动`（`revert`，本地改动与冲突一起没了、回到干净基线）；
- 顶部「全部取用」可把某一策略「套到所有行」，勾掉的行不参与；执行走「处理勾选的 N 项」两步确认，同一种策略的多个路径合并成一条 `svn` 命令发出；
- 处理完会自动重读状态：某条冲突没了就从列表里消失（已选策略与勾选状态按路径保留），整个目录清完则窗口自动关闭；「不完整」条目（~，工作副本没读完）resolve 动不了，窗口只提示它要靠「更新」找回；
- 主页工具条在汇总有冲突时给出「冲突 N 项待处理」的可点入口，悬停按目录列出各自的项数，点下去打开第一个有冲突目录的提交页。

### 提交流程

- 通过 `svn status --xml` / `git status --porcelain` 列出待提交内容，自动识别 新增(A) / 修改(M) / 删除(D) / 替换(R) / 未版本化(?) / 已丢失(!) / 冲突(C)，按类型着色，每行复选框可勾选；
- **新增 / 删除可与修改一并提交**：勾选的未版本化项自动执行 `svn add`（Git 为 `add -A`），已丢失项自动执行 `svn delete`，随后一次 `svn commit`；提交前重新读取状态，未进入调度的条目将列为「已跳过」；
- 检测到本地未更新至最新时，提交页常驻提示条；首次点击提交仅显示后果并转为「仍要提交 N 项？」，再次点击方才执行，「撤销全部修改」同为两步确认；
- 提交备注为多行文本：SVN 可留空、不预填；Git 必填。SVN 通过临时 UTF-8 文件传递说明，中文不乱码；
- 点选文件即读取 `svn diff` / `git diff` 并以增删行着色渲染，可重新读取或转交 Beyond Compare 对比；
- **本目录的两套规则写在同一个窗口里**：目录行「更多 → 差异过滤与提交屏蔽」打开弹窗（不必进入上传页），两个多行框各装一份、一行一条、都存配置长期生效——上面是差异比对的名称筛选（`bc_filter`，只影响差异比较；原先目录行「更多」里的行内编辑器已移除，这里是唯一入口），下面才是屏蔽可提交项（`commit_excludes`，决定会不会被提交）；两处各改各的、互不牵连；
- **写完点「确认」**：关掉窗口并按刚写下的两套规则重读本目录一次，主页的「待提交 N」「本地差异 N」与窗口里的命中数一起跟上；用标题栏 ✕ 关掉则只在筛选条件变过时重跑一次差异比对；
- **按名称过滤留在提交页顶栏**：单行输入框只改本页显示、命中处高亮，多关键字用 `;` 隔开；被过滤掉的条目只要还勾着照样会提交，与屏蔽规则不是一回事；
- **屏蔽可提交项长期生效**：屏蔽规则按目录写入配置（`commit_excludes`），命中的条目不进提交清单、不计入主页「待提交 N」，「全部上传」与提交前的状态复核同样会把它拦下。规则窗口按最近一次读取的完整清单现算「当前命中 N 项」，提交页顶栏的「显示屏蔽的 N 项」开关只负责把这些行灰色列出来核对，勾不动；
- 屏蔽规则语法同「本地差异比对」的名称筛选：结尾 `\` 表示目录、`*` 与 `?` 通配、`.\` 锚定根目录、`#` 开头为注释，一行一条且无需手写 `-`；不带锚定的多段路径（如 `A\B\target\`）会自动补成 `./A\B\target\`，否则永不命中；
- **唯一不被屏蔽覆盖的写操作是「撤销全部修改」**：它执行 `svn revert --recursive` 整目录倒回，SVN 侧没有排除参数，被屏蔽的改动会一并丢弃且不可恢复，按钮悬停说明与确认提示会写明本目录有几项已屏蔽。

### 本地差异比对

- 在「更多 → 绑定对比对象」中为工作副本绑定一个目录（通常为真正编写代码、不受版本控制的「本地开发侧」），程序将随每次检测自动逐文件比对，目录行报告「本地差异 N 项」或「本地无差异」，点击即可选中该目录并打开 Beyond Compare；
- **判定口径与 Beyond Compare 默认规则一致**：大小与时间戳均相同者直接视为一致；仅差 UTF-8 BOM、CRLF↔LF、行尾空白、末尾换行者视为等价（不计入差异）；支持同一套名称筛选条件（排除规则），`.svn` / `.git` 永远排除；
- 这里的筛选条件只影响差异比较，不决定「会不会被提交」；「更多 → 差异过滤与提交屏蔽」窗口里的「屏蔽可提交项」用的是同一套语法、各存各的（`bc_filter` 与 `commit_excludes`），互不影响；
- 内容核对受 60 秒时间预算约束，超时未读完的文件单独记为「未核对」；仅在 0 差异且 0 未核对时才显示「本地无差异」；
- 支持导出本地差异诊断报告（含大小、时间、判异原因、首个差异字节与行摘录），便于问题排查。

### Beyond Compare 联动

- 顶部按钮按当前选中目录匹配 BC 中已保存的文件夹对比记录（`BCSessions.xml`），命中后直接打开；
- 提交页以 `svn cat -r BASE` / `git show HEAD` 导出基准版本，供 BC 并排对比「基准 ↔ 本地」；
- 绑定对比对象后，对比目标与筛选条件记录于本程序配置，不再依赖本机 BC 会话记录，更换机器后同样可用；
- 设置中可指定 BC 路径（自动寻找或手工指定）、服务器端摆放位置，以及写入 BCSessions.xml 的会话默认值（比较内容 / 比较文件名大小写，写入前自动备份）。

### AI 工作日志

- 顶部「AI 日志」按钮开启日志模式后，各目录提交记录页中本人提交的版本行出现勾选框，勾选的提交跨目录、跨页面收集保留；
- 在「AI 工作日志」窗口中将所选提交整理为「文件名 + 修改内容」文本，调用 **OpenAI 兼容的 `/chat/completions`** 接口（如阿里云百炼 DashScope 的 Qwen 系列模型），一次性取回整篇日志；接口地址、API Key、模型名与口吻均在设置中配置；
- **密钥安全**：API Key 通过 curl 配置文件传递，不出现在命令行参数中（任务管理器不可见），临时文件用后即删；请求使用系统自带的 `curl.exe`，不为程序引入额外 HTTP 依赖；内网地址自动绕过系统代理；
- 生成结果可直接编辑，提供「复制全部」「重新生成」；所选提交涉及文件超过 20 个时提示可能消耗较多 token。

### 界面与其他

- **主题**：默认跟随系统，顶部按钮在 跟随系统 → 浅色 → 深色 间循环，标题栏即时生效；主题色可自定义（默认靛蓝）；
- **字号与字体**：字号提供 小 / 标准 / 大 / 特大 四档整屏缩放；字体下拉仅列出本机已安装的中文族，「自动」永远在首位，本机缺失配置所记字族时自动回退，不会因缺字体崩溃；
- **输出记录**：底部面板实时显示每条命令及其输出（UTF-8 / GBK 自动识别），按 命令 / 成功 / 警告 / 错误 分色，支持自动滚动与清空；
- **设置持久化**：svn / git / BC 路径、仓库账号、提交记录条数、自动刷新间隔、AI 接口配置、主题、字号、字体、更新源等全部写入配置文件；
- 启动即最大化，exe 内嵌应用图标（含窗口 / 任务栏图标），右下角内嵌吉祥物贴图。

## 快速开始

1. 下载或构建 `repo-manager.exe`（见[构建指南](#构建指南)）；
2. 双击运行，程序将自动寻找本机 `svn.exe` / `git.exe`；
3. 将工作副本文件夹拖入窗口（或点击「添加」选择文件夹）；
4. 在对应目录行按需执行 更新 / 上传 / 历史 等操作。

## 构建指南

### 一键构建

```bat
build.cmd
build.cmd 1.2.4.1      :: 同时将本次内嵌版本号设为 1.2.4.1
```

脚本自动寻找 MinGW-w64 工具链（优先仓库内 `tools\mingw64`，其次 MSYS2 常见位置，最后 `PATH`），并在缺少 `libpthread.a` 时自动从 rustup 补齐；任一步骤失败均会停止并显示原因。

产物：`target\release\repo-manager.exe`（单文件，无运行时依赖）。

### 版本号

程序内嵌的版本号来自根目录 `version.txt`（`build.rs` 编译时注入，界面显示与更新检查均使用该值）：

- 格式不限，`1.2.4` / `1.2.4.1` / `1.2.4-加固` 均可；`build.cmd 1.2.4.1` 等价于先写入该文件再编译；不带参数时沿用文件现有内容，直接 `cargo build --release` 亦同样生效；
- `Cargo.toml` 的 `version` 仅作兜底（`version.txt` 缺失或为空时使用），因其必须为合法 semver，无法容纳四段版本号；
- 请勿与发布用 `version.txt` 混淆：`tools\update_server.py` 读取的是 exe 或脚本旁的同名文件，仅用于发布时推断版本号。

### 手动构建

```bat
:: 仅需一次：安装 Rust（GNU 工具链，无需 Visual Studio）
winget install Rustlang.Rustup
rustup default stable-x86_64-pc-windows-gnu

cargo build --release
```

> `rustup default stable-x86_64-pc-windows-msvc`（需安装 Visual Studio 生成工具，图标编译走 `rc.exe`）。

## 版本自动更新

程序内置轻量自动更新机制，提供三种更新源，**自托管时服务端仅需静态文件托管能力**。

### 更新源

设置 → 版本更新中三选一：

- **官方源**（默认）：读取 GitHub 最新 Release（`releases/latest`），取其 exe 资产与 GitHub 提供的 sha256 摘要，无需填写任何地址；
- **测试分支**：读取仓库 Release 列表而非仅最新发布，勾选了 pre-release 的发布即测试版，仅选择该源的客户端会收到，版本号后标注「测试版」；
- **自定义源**：读取「服务端地址」下的 `latest.json`（内网地址自动绕过系统代理）。

### 客户端机制

1. 启动后后台检查更新；若开启「自动检查」，此后每 5 分钟静默检查一次；
2. **是否有新版以文件为准**：将更新源给出的 `sha256` 与本地正在运行 exe 的 sha256 比对，不同即提示——同一版本号重新发布的构建亦能被发现（源未提供 `sha256` 时退回版本号比较）；
3. 顶部栏显示「↑ 新版本 Vx.y.z」按钮，点击弹出确认对话框（版本号、发布时间、更新说明多行展示）；
4. 确认后于程序内下载新版 exe → sha256 校验（不符则删除重下）→ **原位替换**：正在运行的旧 exe 改名让路、新文件顶替正式名（同卷原子改名，支持中文路径，全程无需收尾脚本）→ 重新启动新版，启动时自动清理遗留的旧版文件。

### 自定义源协议（latest.json）

```json
{
  "version": "1.2.0",
  "url": "files/repo-manager_1.2.0.exe",
  "notes": "修复了 xxx\n新增了 yyy",
  "sha256": "发布时自动写入；客户端据此判断有无新版，下载后亦以此校验",
  "published_at": "2026-09-07 10:00:00"
}
```

- `url` 相对 `latest.json` 所在目录拼接，亦可填写完整 http(s) 地址；
- `notes` 支持换行（`\n`），客户端按原文多行展示；
- 版本号仅用于界面显示，写法不限；客户端判断更新依据 `sha256`，与内嵌版本号不一致亦不会反复提示。

### 发布流程

**方式一：拖拽发布（推荐）**

将新版 exe 拖至 `tools\publish_drop.bat` 上：

1. 依提示填写版本号：回车沿用默认（文件名版本 > version.txt > 上一发布版本）；`+` 为补丁号 +1，`++` 为次版本号 +1，亦可直接填写任意格式，`q` 取消；
2. 填写更新说明：输入中的字面 `\n` 将转为真实换行；多段说明建议置于 `notes.txt`（exe 旁或脚本旁，自动沿用）；
3. 脚本将 exe 拷入版本目录、计算 SHA256、生成 / 覆盖 `latest.json`。

**方式二：命令行发布**

```bat
python tools\update_server.py D:\update_root --publish repo-manager_1.2.0.exe --notes "修复xxx"
```

### 托管更新服务

零依赖脚本自带静态托管（Python 3.8+，无需任何第三方库）：

```bat
python tools\update_server.py D:\update_root --serve --port 8666
```

客户端「设置 → 版本更新 → 服务端地址」填写 `http://<本机IP>:8666` 即可。以 nginx / IIS 托管同一目录效果相同。版本目录的确定顺序为：命令行参数 > 脚本旁 `update_root.txt` 第一行 > 脚本旁 `update_root\`。发布仅写入文件，服务运行期间无需重启，客户端下次检查即生效。

## 配置与运行期文件

| 文件 | 用途 |
|------|------|
| `%APPDATA%\RepoManager\config.json` | 配置文件（目录列表及分组 / 标记 / 对比对象、各目录的名称筛选 `bc_filter` 与提交屏蔽规则 `commit_excludes`、svn / git / BC 路径、账号、AI 接口配置、提交记录条数、刷新间隔、主题、字号、字体、更新源等）；可用记事本编辑，带 UTF-8 BOM 亦能识别 |
| `%APPDATA%\RepoManager\panic.log` | 异常日志（界面程序无控制台，panic 信息写入此处；有新增内容时界面顶部会提示） |

程序曾名 svn_manager：首次启动时将把旧目录 `%APPDATA%\SVNManager\` 整体复制至新目录（旧目录原样保留、不覆盖新目录已有配置），开机自启的注册表项亦同步接管。

其他须知：

- 仓库账号以明文保存，请谨慎在共享机器上使用；
- 所有 svn 命令均带 `--non-interactive`，需要交互输入（如首次接受证书）时直接返回错误并显示于输出面板；
- 主题默认跟随系统，可随时通过顶部按钮或设置页切换。

## 说明与限制

- 依赖命令行工具：SVN 仓库需 `svn.exe`（TortoiseSVN 安装时勾选 *command line client tools*），Git 仓库需 `git.exe`；
- 「清理工作副本」「解决冲突」「修改仓库地址」为 SVN 特有操作，Git 目录的菜单中不提供；
- 凭据默认使用 svn / git 各自的缓存机制，亦可在「设置 → 仓库账号」填写；
- AI 工作日志与自定义更新源的接口地址 / 密钥由用户自行配置，密钥以明文保存在本机配置文件中；
- 自动更新的下载与校验均在程序内完成，替换环节采用同卷原子改名，不借助外部下载脚本，以避免被安全软件误判；
- `tools\mingw64`（构建用工具链）不随仓库分发，可自行准备 MinGW-w64 或改用 MSVC 工具链。
